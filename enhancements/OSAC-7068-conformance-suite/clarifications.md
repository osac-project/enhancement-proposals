# Clarifications - OSAC-7068

Questions raised while clarifying the PRD, and the decisions the PRD reflects. Each `[Clarify: <ID>]` marker in [prd.md](prd.md) points to an entry here.

| ID | Question | Decision | Reflected in |
|---|---|---|---|
| R1.Q3 | What makes an installation pass, and how does a user act on a failure? | The verdict is a list of named checks, each stating its rule and its remedy. The installation passes when no check fails. The core reports this installation-level verdict only; the per-component verdict (every blocking component test that applies passes and every selected profile passes) is deferred with provider-side tests and component identity. | In Scope, verdict item; design Result rules and Report for the installation verdict; design Non-Goals for the deferred component verdict |
| R1.Q4 | How are tests that are not yet proven in OSAC CI handled? | A test is `blocking` or `informing` as its domain declares. A test may start `informing` until a human owner promotes it to `blocking`, and a domain may declare its tests blocking from the start. No domain declarations exist in this release, and the shipped networking Netris settings check is `informing`. An informing failure is reported and does not fail the run. | In Scope; user stories; design Catalog and selection |
| R1.Q5 | How does the suite decide which tests to run? | Selection is declared: every conformance test carries selector labels, the configuration names the profiles the run selects, and the suite expands them into selectors (the generic set always applies). The plan is their union. It is written out and printed, so the set can be reviewed, kept, and rerun. | In Scope, test selection item; design Catalog and selection and Plan |
| R2.Q1 | Are upgrade and air-gapped modes in scope? | No. The suite runs against an installed release; upgrade and air-gapped modes are out of scope. | Out of Scope |
| R2.Q2 | Does the new suite image replace the networking-only image, or ship alongside it? | One image per OSAC release, tagged with that release. It replaces the networking-only image, and no release ships both. | In Scope, first item |
| R2.Q3 | What is the conformance rule for a component? | Every blocking component test in the plan passes and every selected profile passes; otherwise the component is `in progress`. The core computes no per-component verdict, because it ships no component identity or provider-side test; this rule takes effect when those follow-up stories ship. | In Scope, verdict item; the rule is deferred per design Non-Goals |
| R2.Q4 | Does OSAC verify or certify reports, or enforce a domain's support condition? | No. The report is self-reported, and each domain states its support condition without OSAC enforcing it. | Out of Scope; design Security Considerations |
